# M2.4 — Evidence Engine

## 1. Objective

- 用户价值：把已摄取用户来源与 M2.3 Research Results 转换为可追溯、可去重、可判冲突、可判时效、带权威等级与使用策略的 Evidence Ledger，而不是把“来源里有一段文字”或“搜索到了一个结果”直接当成可上页事实。
- 本轮边界：Evidence candidate contract、Research Result → auditable partial Web Source materialization、claim normalization、stable Evidence IDs、exact deterministic dedupe、support/conflict/freshness/authority/use policy、research cycle semantic completion、G2/validation/CLI 与故障测试。
- 明确不做：LLM 自动语义改写/事实抽取、网页正文抓取、近义语义聚类、Block-level evidence binding、Outline gap routing、Narrative/Slide 自动生成、搜索供应商适配器。
- 退出条件：任何 Production Evidence claim 都可追到 Source Ledger + locator；Research summary 在未抓取正文时只能 provisional/qualified；stable Evidence IDs 在重跑/插入/去重后不漂移；冲突/陈旧/低可信/禁止使用来源 fail closed；research cycle 只有在 Run 结果已物化且 Evidence policy 通过后才可语义 complete；Round A 无未修复 Critical/Major，Round B Submodule Gate PASS。

## 3. Decisions

| ID | 决策 | 依据 | 可逆性 |
|---|---|---|---|
| D-401 | Evidence Engine 只裁决结构化 EvidenceCandidate；不在 deterministic core 中假装完成 LLM 语义事实抽取。M2.4 可从一个 Source Chunk 形成一个保守 candidate，后续模型只能通过同一 candidate contract 接入。 | 能力诚实 | 高 |
| D-402 | `claim_key` 采用保守 Unicode/空白/展示标点规范化，百分比、单位、比率、小数、正负号和数值区间保留；仅 exact normalized duplicate 合并。Production core 不做不可解释的模糊语义合并。 | 稳定 ID / 避免误合并 | 中 |
| D-403 | Existing Evidence 的 canonical claim_key 继续占用原 `EVD-*`；新 claim 只分配下一个 ID，不因排序/插入重新编号。 | ID 稳定 | 中 |
| D-404 | Research Result 物化为 `kind=web`、`parse_status=partial` 的 Source Ledger 记录和不可变 Source Snapshot。Snapshot 只包含 provider 返回的 title/summary/URL/metadata，并明确“远程正文未抓取/核验”；因此它只能产生 indirect/provisional Evidence。 | Result ≠ fetched source | 中 |
| D-405 | Web source identity 使用无凭据规范化 HTTP(S) URL；同 URL 复用同一 Source ID，并按稳定 `RSLT-*` 合并多个 Run/provider 的结果，刷新只替换同一结果，不创建别名 Source ID。 | 来源身份 | 中 |
| D-406 | Support 决策 fail closed：无 source ref → unsupported；冲突 → disputed；Research-summary-only → provisional；直接可定位的用户/已摄取来源在无冲突/时效阻断时可 verified；inference/assumption 永不自动 verified。 | G2 / 事实安全 | 中 |
| D-407 | Authority 使用 Source Ledger `authority_tier` 聚合；Engine 记录 strongest/weakest tier 与 reason codes，不把 source tier 本身当真值。 | 来源质量可解释 | 高 |
| D-408 | Freshness 只在有明确可计算 cutoff 时作 deterministic stale/current 判断；无法解析的自然语言 freshness 要求记 unknown 并触发 qualification，不伪造时效结论。 | 可验证性 | 高 |
| D-409 | `use_policy` 由 support + source allowed_use/confidentiality + freshness/authority 推导；`disputed`/`unsupported`/do_not_use source 一律 `do_not_use`，provisional/stale/unknown freshness 至少 qualification。 | fail closed | 中 |
| D-410 | Semantic `research_cycles.status=complete` 只能由 Evidence Engine 在对应 Research Run complete、结果已物化且 cycle source/evidence checks 通过后写入；M2.3 Runtime 自身仍不能推进 G2/G5A。 | ADR-0011 | 中 |
| D-411 | M2.4 使用 Artifact Runtime 作为 Source/Evidence Ledger 的唯一事务写入口；Research materialization 先发布 immutable snapshots，再用 optimistic-locking 更新 Ledger。 | M1/M2.1 一致性 | 中 |

## 5. Quality and risk controls

- 不把 provider summary 写成“网页原文”；Research-materialized Source 必须 `partial`，warning/notes 必须明确正文未抓取。
- URL 仅 HTTP(S)；规范化不丢 query 参数，不自动访问网络。
- Evidence source refs 必须存在，若对应 Production Source 有 Snapshot 则 locator/chunk identity 必须可验证。
- Dedupe 只做可解释 exact canonical match；语义近义项保留独立，等待 reasoning/model 层显式给出 merge decision。
- Conflict 不靠字符串否定词猜测事实；deterministic core 使用显式 `conflict_key`/`stance` candidate facts，缺失时不伪造冲突判断。
- Freshness cutoff/日期必须 ISO 可解析；否则 `unknown` + qualification。
- 任何 manual/out-of-band Ledger 变更继续由 Artifact Runtime hash/version conflict 阻断。
- Evidence Engine 不降低现有 G2：unsupported/disputed 只有 `do_not_use` 才能留在 Ledger 而不成为可用事实。
