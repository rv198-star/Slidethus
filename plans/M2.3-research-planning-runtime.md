# M2.3 — Research Planning and Runtime

## 1. Objective

- 用户价值：让 Slidethus 能围绕 Brief 和当前 Outline 形成有界研究计划，经过可替换 ResearchProvider 执行，并把 query/task/result lineage、缓存、恢复、失效和离线状态持久化为可审计运行时事实。
- 本轮边界：实现 orientation / targeted 两阶段 Research Plan、Research Run、provider-neutral execution、query-level cache、resume、explicit invalidation、offline degradation、运行时 Schema 与测试。
- 明确不做：把 Research Result 自动判定为 Evidence、来源权威裁决、冲突/去重/时效结论、外部搜索供应商适配器、Web 抓取正文、Block evidence binding、最终叙事/视觉生成。
- 退出条件：同一研究计划可重复获得稳定 IDs；任务逐个可恢复；缓存命中/过期/失效语义可验证；provider 失败不丢已完成任务；offline 不伪造结果；orientation/targeted 都有真实运行时 lineage；Round A 无未修复 Critical/Major，Round B Submodule Gate PASS。

## 2. Current state

- 依赖基线：M2.1 Ingestion Core 与 M2.2 Multi-format Adapters 均已通过 Submodule Gate；进入 M2.3 前来源侧完整测试为 92 passed。
- 已存在：`ResearchQuery` / `ResearchResult` / `ResearchProvider` 占位协议；Evidence Ledger 的 `research_cycles` 已区分 orientation/targeted 和 outline version；G2/G5A 已检查 cycle completion。
- 缺口：无 Research Plan/Run Schema、provider identity、task 状态、结果身份、缓存/TTL、resume、explicit invalidation、offline provider、运行时校验或两阶段 planner。

## 3. Decisions

| ID | 决策 | 依据 | 可逆性 |
|---|---|---|---|
| D-301 | Research execution 先形成独立运行时事实，不在 M2.3 自动升级为 Evidence。只有 M2.4 可把研究结果裁决/注册为可用 Evidence。 | 防止“搜索到 = 事实成立” | 高 |
| D-302 | `research_run.schema.json` 是非 catalog 的运行时 Schema，存放于 `.slidethus/research/runs/`；Evidence Ledger 仍是语义事实源。 | artifact/runtime 分层 | 中 |
| D-303 | Plan ID 与 query/task IDs 由规范化计划确定；Run ID 进一步绑定 provider identity。 | resume / audit | 中 |
| D-304 | Provider 必须声明 name/version；缓存 input key 绑定 provider、query、cycle kind、outline version、freshness、source tiers 与影响结果的 limits。 | provider-neutral + cache correctness | 中 |
| D-305 | Query cache 使用 immutable result snapshots；显式 invalidation 通过 generation marker 使旧快照失效，不覆盖历史结果。 | 审计与恢复 | 中 |
| D-306 | Run manifest 是可恢复的运行时状态：每完成一个 task 原子更新；失败后重跑只执行未完成或已失效 task。 | crash-safe resume | 中 |
| D-307 | Offline provider 不返回伪造结果；运行结果显式 blocked，并由后续 capability policy 决定 D3/D5。 | 能力诚实 | 高 |
| D-308 | Orientation planner 基于 Brief 的标题、目的、期望结果、受众和 freshness 形成有界问题；Targeted planner 基于当前 Outline 的 headline/takeaway 形成逐页问题。Planner 只定义“查什么”，不判断“事实是什么”。 | ADR-0005 | 高 |
| D-309 | M2.3 不修改 Source Ledger 或 Evidence claims；M2.4 负责 research result → source/evidence materialization。 | M2.4 职责边界 | 中 |

## 5. Quality and risk controls

- 单元测试禁止真实网络；Fake/Static provider 只存在测试或 fixture 层。
- Provider 返回值必须有 locator、title、summary、source tier、retrieved_at；URL 如存在只接受 HTTP(S)。
- Query/result/run 数量和字符串长度有显式上限；不允许无限搜索或无限结果。
- Cache lookup 必须验证 Schema、input key、provider identity、generation、result identity 与 snapshot hash；损坏 cache fail closed，不静默跳过。
- Run path 固定在工作区 `.slidethus/research/runs/`，拒绝路径逃逸。
- Provider version、freshness requirement、preferred source tiers 或结果相关 limits 改变不得误用旧缓存。
- Targeted run 必须绑定明确的当前 `outline_version`；orientation 的 outline version 必须为空。
- M2.3 运行成功不等于 G2/G5A 自动通过；只有后续 Evidence materialization 完成后语义 cycle 才可完成。
