# v0.8.0 发布执行记录

## 1. Objective

- 用户价值：把当前恢复后的宿主设计链路与模块化技能套件固定为可下载、可安装、可回溯的 v0.8.0。
- 本轮边界：版本、发布文档、单 Python 检查、分发包、Git 提交/标签/GitHub Release。
- 明确不做：新功能、新行业案例、多 Python 版本审计、PyPI 上传，以及将 M6.6 / v1.0 标为验收通过。
- 退出条件：必要检查通过，仓库外同版本 Python 安装验证通过，远端提交/标签/发布附件一致。

## 7. Review

- 核对版本边界：仅 package/runtime/README 变为 0.8.0，provider/schema 的独立版本号不批量改写。
- 核对 v1.0 边界：M6 验收逻辑保留，测试中的版本漂移输入改为从当前版本构造，避免旧字面值失效。
- 核对发布范围：不扩展案例，不新增依赖，不改已认可设计；发布前复查 diff 与包内容。
- 构建缓存问题：首次 Wheel 比对发现旧 `build/lib` 中有 7 个回退前的多余文件。将旧构建目录及未准入 Wheel 移到本轮临时目录保留，重新构建后逐文件核对通过；发布附件仅使用重建包。以后发布必须使用干净构建目录，并核对包与源码集合，不能仅凭 build 成功判断内容正确。
- 历史 CI 失败（run `33332244793`）：只安装 Python 依赖，没有安装已有 Node renderer 的锁定依赖，导致 `jszip` / renderer 不可用并连带阻断 M4/M5。CI 补上既有 Node 22 基线与 `npm ci --prefix renderers/pptxgenjs`，不增加生产依赖、不删除失败测试；仍只有 Python 3.11 一个任务。
- 暂存内容检查：90 个文件，无 dist/build/venv 进入 Git，无凭据格式命中；Taste 上游与 `source_material/` 没有改动。历史计划的行尾空格仅做格式清理。
