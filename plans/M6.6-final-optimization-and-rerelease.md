## 1. Objective

把用户认可的视觉工作方式接入正式 Create 工作流，使设计判断、图片/图表规划、全篇风格和真实 PowerPoint 文件在同一条路径上成立，然后再决定新的预发布。

不是回放被撤销的实现，也不是把酒店低奢版固化成默认模板。本轮只推动三个结果：真实设计判断有可用入口；判断能影响正式页面；交付证据对应真实文件。

范围约束：

- 只改 Create 所需的共性能力；其他工作流保持既有行为。
- 不扩展行业、场景或大规模 corpus；历史三案作为已有反馈和视觉参照，结构测试使用去主题输入。
- 不规定每页必须有图片、图表，不用固定四页、固定密度、固定色系定义质量。
- 不改用户已经接受的酒店 PPTX，不继续修补已隔离的失败候选。
- 本次先完成事实复核、执行顺序和状态纠正；不在方案阶段迁回生产代码、改版本号、打标签或发布。

退出条件是正式路径生成的样板及全篇 PPTX 获得真实目标渲染器验收，而不是新增字段齐全、测试全绿或包装可复现。

## 3. 复核结论：保留目标，纠正实现顺序

### F-01｜获认可的成品与正式工作流不是同一个验收对象

归因报告明确记录，酒店初稿使用定制渲染脚本，未形成正式 Packet/Layout/Visual System/M5 闭环。低奢统一版证明了冻结视觉语法、按信息关系变化页面的价值；不能据此推出当时默认 Create 已能复现该品质。

后续恢复计划也记录：正式 scoped render 因缺少 `production_visual` provider 而阻断，四页样板则由临时脚本制作。该脚本没有 `addImage` 调用，有原生图表，但不是 Taste 驱动的原生视觉原型。

**判定：已证实存在验收路径分离；尚未证明每次视觉退化都由同一段代码引起。** 新验收必须从同一正式入口、同一工件链得到样板和全篇，不允许再用手工旁路证明框架能力。

### F-02｜视觉判断没有因增加 Policy 而自动出现

基线 `src/slidethus/art_direction.py::TasteSkillArtDirectionProvider.propose` 固定 editorial 配色、字体尺度、页面处理及组件列表。恢复分支新增 `propose_planning_policy`，主要产生“每 Block 有决策”等固定约束，默认实现仍是同一个确定性 adapter。

本次只读探针：保持模式、语言、布局相同，将不含品牌信息的用途从 `opaque-a` 改为 `opaque-b`，结果 `design_read` 改变，`direction` 完全相同。该探针证明没有从用途文本推导视觉方向，不证明任意文本变化都应换设计。

**修订：先提供真实宿主推理 proposal 的提交、准入、持久化和消费路径。** Taste 作为默认固定资源；无推理能力时明确 generic/degraded，不能用固定 proposal 代替已执行设计判断。

### F-03｜可执行规则仍可能只是硬编码默认值的另一种写法

恢复分支 `src/slidethus/visual_rules.py::build_executable_rules` 生成固定 surface、hero、case、matrix、timeline、process 规则。它消费颜色/字号等属性，但没有把 `page_role_treatments`、`component_variants`、`deck_rhythm` 翻译为对应的构图与组件行为。

本次在实际字段位置 `shape_rules` 中，将上述三组输入分别改为另一组页面处理、无边框组件、图文节奏，22 条生成规则完全不变；对照修改 `colors.surface` 则会改变规则。这个结果比“规则存在且 hash 正确”更直接地说明传播仍不完整。

另外，历史 `design_planning_policy.py::resolve_policy_items` 对无机器 constraint 的建议项直接写 `implemented`，理由却是仅被 admitted。准入不等于兑现；不能把这种状态迁回新实现。

**修订：只给已支持、确实影响输出的设计属性执行承诺；不支持的方向显式回流或报缺能力。** 合理的审美建议交由真实页面评审判断，不用语义 hash 代替判断，也不为此先建一套通用美学规则语言。

### F-04｜载体不足与文件修复提示必须分开处理

缺图片可能发生在“没有提出需求”“没有取得资产”“区域没有绑定”“后端没有嵌入”中的任一步；不能一律归给渲染器，也不能由空资产库存推出无需图片。

历史 carrier 修复又把“三个以上同单位数值”作为生成图表的条件。它不是行业特例，但同单位不保证可比，两个数也可能值得比较。是否使用图表应由命题、数据口径和沟通目的决定，确定性代码检查数据与输出，不按数值个数决定审美或论证需要。

文件侧，先前 PowerPoint 修复前后的包差异已发现 slide4 存在负数 `a:ext/@cy`（`-256032`、`-329184`），修复副本改为零。它是已确认的非法几何证据，但最后一个临时修复版未完成 PowerPoint 复验，不能宣称唯一根因已确认或问题已解决。

**修订：正式后端做通用几何/包结构防护；交付目标为当前用户的 Microsoft PowerPoint。** 不增加 LibreOffice 兼容补丁；其他宿主可保留其预览适配，但不得冒充本次 PowerPoint 验收。

### F-05｜历史审计有效，但实现完成度和产品状态失去了同步

历史收敛计划最终正文仍写 Schema/service/runtime 待实现，而撤回快照已有大量实现和 RC 打包报告。RC 报告确实区分了包装通过与 Stable 不发布，不能说它完全没有披露风险；问题是这不足以证明用户会实际调用的 Create 路径已经能做出合格成品。

当前恢复基线也有真实冲突：README/TASKS 是 `DO NOT RELEASE`，Skill 入口仍写 `v1.0 Release Gate: PASS`。

**修订：本轮先纠正当前入口状态。** 后续任何“已完成”必须绑定实际入口、输入、输出、验证和限制；历史里程碑 PASS 不冒充当前发布授权。

## 5. Work breakdown：三个实现批次，逐个止损

### Batch 1 — 打通真实设计判断与页面规划

产出：一个可运行的宿主 reasoning adapter/结构化 proposal 准入入口；一个经准入的 planning 方向；由其驱动的 P5A/P5B；最终 Packet。前后只保存各自阶段事实和引用，不在上游写未来样板 ID。

- 先调整 Skill 的调用方式与 provider 注入路径，再扩展必要合同，不用新增字段替代实际调用。
- 受众、观看/分发方式和沟通目标仍由 P0 Brief 拥有；展示姿态不是风格模板键，同为对外展示也不必采用同一种视觉语言。
- 区分资源内置、Taste-informed 推理、Taste-generated 原生原型。需要校准视觉方向时，Taste 真正驱动隔离 HTML/CSS 等原生原型；原型不写正式 Gate、不作为 PPTX 验收。
- 批准方向之后，翻译回正式规划；内容不在 renderer 中重新创作。
- P5A 显式提出有职责的视觉资产需求，并评估定量关系用 chart/table/metric/prose 哪种表达；无可比数据不造图。
- 最小数据要求：有来源的数据值、标签、单位/口径、时间范围、必要变换说明。可以复用现有 asset/Evidence 表达；表达不了时收窄声明或阻断，不用伪造 lineage 填空。
- 缺图进入获取或正式重规划，不能把缺图悄悄变成无需图。
- 旧工件可以保留在其原有路径；进入新路径时重跑受影响规划，不能通过迁移补造历史设计理由。Schema 与 packaged mirror 同步，未接入的工作流不被隐式强制迁移。

验收：本次 4 页只是测试规模，不是产品配额；选用现有材料，覆盖真实图片、数字图表、关系表达、正文层级这些已暴露风险。可以复用页，不强制一页一种。另有文字正确时保留文字、无数据时不造图的负例。

停止：如果真实 proposal 尚不可被正式入口消费，不继续建校准/追踪子系统，也不交付手工旁路 PPTX。

### Batch 2 — 用同一正式路径兑现设计，并验证样板到全篇

产出：消费获准设计与布局的真实 PPTX、嵌入媒体/原生图表、PowerPoint 逐页证据、一次用户样板判断；接受后才生成同源全篇。

- 以布局和组件行为验证传播；改变一个适用设计属性，应改变对应 IR/真实输出；不适用或等价变化不强求差异。
- 优先替换固定 card/family 默认逻辑；不把旧分支原封不动包装成另一套 rule DSL。
- 列出后端真实支持的几何、文本、资产、图表能力；不依靠自报 `production_visual` 证明美学质量。
- lab、样板和全篇路径分离；样板选择/批准引用已存在的输入与输出。只读查看部分页面不发布全量 G7–G9，不回写上游冻结事实。发生修订则是新版本，不在原 Attempt 边审边改。
- 对连接线方向、非负 extent、媒体关系、图表、字体做通用测试；不靠删除 Notes/部件的“净化版”试错链解决未知修复提示。
- 在 PowerPoint 打开原始候选文件，无修复对话框；检查页数、字体、图片、图表标签和全篇风格。修复后能显示不能算原文件通过。

停止：样板没过，不扩全篇；全篇漂移先定位最早责任阶段；若同类修复连续失败且无新证据，停下归因，不再叠加第三个补丁。

### Batch 3 — 新候选包与发布决定

产出：锁定提交构建的候选 wheel/Plugin、干净安装验证、一次真实任务的完整交付与报告；发布需要单独确认。

- 从干净环境安装构建包，不能依赖仓库外临时脚本/未入包资源。
- 新增行业不是前置条件；真实任务可采用当前待完成的 AI 中小微企业课题，但换工作区、从正式 Create 入口运行，保留实际设计判断与文件证据。
- 旧 hotel 成品作为人类审美参照，不能要求新题目复刻颜色、留白或页面布局。
- 旧 API/workflow 回归不变；缺 provider、缺资产、旧预览、审批后上游变化均诚实阻断或披露降级。
- 先明确新 RC 的实际能力与限制，再定版本；不复用旧 RC 的 PASS，不在本方案中授权 tag/push release。

停止：未取得新的正式路径全篇 PowerPoint 验收，不宣布新的可用 RC；Stable 另行决定。

## 6. Quality and risk controls

本次文档轮不改生产 Python/Node、Schema、Gate 或包版本；仅恢复历史资料、纠正入口状态、建立当前计划。未来主要触达 provider 入口、P5A/P5B、Visual System/IR、PPTX 后端和视觉审阅；每批再以实际失败约束确认必要范围。

最小验证矩阵：

| 对象 | 正例 | 必须保留的负例 |
|---|---|---|
| reasoning | 宿主提交的获准方向影响规划 | 无 provider 不冒充有推理；不只改 design_read |
| representation | 内容职责决定合适载体 | 空库存不免除必要图片；两数/多数字不机械决定图表 |
| grammar | 适用设计改动到达 IR/输出 | metadata 改变而页面不变不能称兑现 |
| 状态与引用 | 先产出后批准，下游只引用已有事实 | 未来引用、样板污染全篇 Gate、过期批准 |
| PowerPoint | 当前未修复原文件直接打开、内容齐全 | 负 extent、缺媒体、旧预览、修复后副本冒充原件 |
| 通用性 | 去主题 ID/文字仍保留结构行为 | 主题词分支、固定图片配额、后端自报审美等级 |

未解决的 Critical/Major 不能用总分覆盖。审美诊断不是新增通用硬阈值；后续待办不是本轮 blocker。
