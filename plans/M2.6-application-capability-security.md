# M2.6 — Application Orchestration, Capability Degradation, and Security Integration

## 1. Objective

- 用户价值：把 M2.1–M2.5 的独立 Production services 连接成一个可恢复、可观察、不会越权或夸大能力的应用入口，从 Brief 和本地 Sources 推进到 G2，并在已有 Outline/Specs 时推进到当前 G5A 或明确返回 P2 rework。
- 本轮边界：M2 application service、capability/degradation decision、Source/Research/Evidence/Gap orchestration、explicit external-disclosure approval、high-risk source isolation、resource budgets、runtime report、CLI 和 end-to-end tests。
- 明确不做：内置搜索供应商、自动生成 Narrative/Outline/Slide Specs、LLM claim extraction、自动把新 Evidence 写回页面、最终视觉/渲染升级。
- 退出条件：用户材料路径可从 resolved Brief 稳定达到 G2；已有规划 artifacts 可在 current-version revalidation 后达到 G5A 或明确 route rework；外部研究缺失、最新性要求、未批准披露、格式依赖缺失和高风险来源均有诚实降级/阻断；重试幂等；Round A 无未修复 Critical/Major，Round B Submodule Gate PASS。

## 2. Current state

- M2.1–M2.5 Submodule Gates PASS；Python 3.11/3.12 全仓库为 146 passed。
- Source、Research、Evidence、Gap/Rework 均有独立 CLI/服务，但没有单一应用级运行事实或一致的降级决策。
- CLI 没有内置在线 ResearchProvider；这必须继续保持 provider-neutral，而不是为了“端到端”写死供应商。
- Source risks 已记录但自动 Evidence orchestration 需要显式隔离 high-risk inputs。

## 5. Quality and risk controls

- CLI does not pretend an online provider exists.
- Provider execution never occurs without explicit disclosure approval.
- High-risk source text remains data and is not automatically promoted to Evidence.
- Explicit degradation records waiver reason, delivery level and missing capability.
- Application report contains only workspace-local operational facts; it is not a Delivery Manifest.
- Every semantic write remains versioned/optimistic and reruns reuse existing snapshots/runs/evidence when unchanged.
- Existing M3 artifacts are only revalidated; they are never generated or silently edited by M2.6.
