# M2.5 — Block-level Evidence Binding, Gap Analysis, and Rework

## 1. Objective

- 用户价值：在进入页面设计前，证明每个显式事实性 Slide/Block 都绑定当前可用 Evidence；缺口能够定位到 slide/block，形成定向研究建议，并通过正式返工边回到 P2，而不是等渲染后才发现无依据内容。
- 本轮边界：Outline/Slide Specs evidence binding audit、policy/qualification checks、schema-backed gap snapshots、targeted query suggestions、current-outline targeted-cycle checks、`OUTLINE_READY/SLIDE_SPECS_READY → EVIDENCE_READY` rework route、G5A/CLI/validation integration。
- 明确不做：LLM 判断任意自然语言是否为事实、自动生成 Narrative/Slide Specs、自动联网研究、语义改写、最终视觉设计。
- 退出条件：显式 required/factual blocks 无 missing/unknown/unusable binding；production provisional/inference/assumption 使用有 qualification；targeted cycle 绑定当前 outline version；gap report 可恢复、可验证、可转 Research Plan；返工状态和下游 invalidation 正确；Round A 无未修复 Critical/Major，Round B Submodule Gate PASS。

## 2. Current state

- M2.1–M2.4 已提供 stable Source/Research/Evidence lineage 与 policy-bearing `EVD-*`。
- Deck Outline 与 Slide Specs 已有 slide/block stable IDs 和 `evidence_ids`，但没有生产级 gap report、qualification contract 或 targeted query handoff。
- G5A 当前只检查 Slide Specs 是否存在以及 targeted cycle 是否完成，不证明 block-level binding 充分。
- State machine 已声明 `OUTLINE_READY → EVIDENCE_READY`，Artifact Runtime 尚无显式 rework transaction API。

## 3. Decisions

| ID | 决策 | 依据 | 可逆性 |
|---|---|---|---|
| D-501 | Gap analysis 只对显式 `evidence_requirement=required` 或确定性 factual slide/block 类型作强制判断；模糊正文不伪装成语义事实分类。 | 能力诚实 | 高 |
| D-502 | Outline slide 与 content block 可选声明 `evidence_requirement=required/optional/none`；Block 可声明 `evidence_qualification`。旧 artifacts 继续兼容。 | 渐进 Schema | 中 |
| D-503 | 可用 Evidence 必须不是 unsupported/disputed/do_not_use；provisional/inference/assumption、stale/unknown freshness 或 qualified policy 需要显式 qualification。 | M2.4 policy | 中 |
| D-504 | Gap Report 是非 catalog、schema-backed、content-addressed runtime fact，绑定 Outline/Slide Specs/Evidence artifact versions/content hashes。 | M1/M2 runtime 模式 | 中 |
| D-505 | Query suggestions 是 deterministic handoff，不代表已经研究；通过公共 explicit-targeted-plan builder 进入 M2.3 Runtime。 | Result/Evidence 分层 | 高 |
| D-506 | Gap 存在时显式 route 到 `EVIDENCE_READY`，保留 G0–G2，标记 Narrative/Outline/Specs 及后续 artifacts draft；不把 gap 当成独立 Phase。 | 状态机合同 | 中 |
| D-507 | G5A 使用当前 artifact versions 重新计算 gap，不信任历史 report；历史 report 只作审计证据。 | stale report 防护 | 中 |

## 5. Quality and risk controls

- 不通过关键词猜测全部事实性内容；明确 requirement 与确定性 page/block types 才形成 blocking issue。
- 历史/legacy Evidence 仍可读取；Production policy checks 只对 M2.4 adjudicated claims执行严格 qualification。
- Gap report 不修改 Outline/Specs/Evidence；rework 是单独显式动作。
- Query suggestion 不自动执行，不绕过 ResearchProvider、Run/Cache 或 Evidence Engine。
- Rework transaction 使用同一 Project State lock/history/validation，不直接编辑 JSON。
- G5A 重新计算当前版本，避免用旧 report 越过 Gate。
