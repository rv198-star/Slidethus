# v0.9.0 Host Create 稳定性修复

## 1. Objective

- 用户价值：让 Host Create 在进入 Artifact Tool 前一次性识别并解释全部确定性阻断；合法返工可达、可提交，已通过预检的输入不再被后续阶段以同一条件拒绝。
- 本轮边界：修复 Issue #2 中的 canonical text-fit、深层回退、上游原子修订、Seed 直接修订、Artifact Tool admission/失败回执和 runtime 诊断；补齐 Schema、文档、ADR 与脱敏回归。
- 明确不做：不降低全局字体 floor，不删除 Office-conservative 检查，不让 renderer 修改语义 artifact，不将用户实验工作区复制进仓库，不把结构通过冒充 Office 视觉通过。
- 退出条件：自动化回归与仓库要求检查全部通过；至少一个端到端 Host Create fixture 生成候选并形成完整回执；真实 Office 检查若本机能力不可用则保持为明确的 release blocker。

## 2. Current state

- 当前 HEAD / 工作区状态：`main` at `18d84f6`，开始前工作区干净，v0.9.0 Pre-release。
- 已存在能力：稳定 artifact registry、G5B planning review、Renderer IR、backend-aware preflight、Artifact Tool host candidate、workflow operation facts。
- 已知缺口：G5B/P7 font floor 与 line-height 不一致；Planning Review target 与状态机回退不一致；上游改动被旧下游跨产物校验阻断；Seed 无直接 revise；adapter 细粒度条件后置；失败无 terminal receipt；Artifact Tool runtime 与 doctor 解析分叉。
- 基线测试：`tests/test_text_capacity.py`、layout/render/state/runtime/M3/PptxGenJS 定向集合通过（2 项依环境跳过）。

| D-005 | Decision | Artifact Tool 每次 attempt 先写 started receipt，再原子更新 terminal 状态 | 失败和超时也必须成为可审计事实 | 中 |

## 5. Quality and risk controls

- 受影响 Schema：`render_preflight_report`（若增加结构化 details）、`host_candidate_receipt`（attempt terminal states）。源码与 `_schemas` 必须逐字一致。
- 受影响 Gate：G5B、G6、G7；P3–P5B rework 与 downstream invalidation。
- 回归范围：text capacity、layout planning、planning review/M3、state machine、artifact runtime、render compile/preflight、Artifact Tool、CLI/doctor、distribution。
- 降级路径：runtime 缺失或 backend 不可兑现时在 Preflight/availability 阶段结构化阻断；不启动 Node，不生成伪候选。
- 安全/来源/版权风险：失败日志截断并清理潜在敏感路径/环境值；不持久化环境变量或完整外部素材正文。

## 7. Review

### 第一轮：开放问题发现

- Critical：无已知项。
- Major：真实 Office 初次检查发现 S-005 表格越界、S-007 底部裁切；根因是 adapter 等分列/行且 Preflight 只验证矩阵结构。修复并正式回到 P5B 后，几何类 Major 清零。
- Minor：Skill Creator 的 `quick_validate.py` 在现有 Python 环境缺少 `PyYAML`；不影响仓库必选检查，也未因此增加生产依赖。

### 修复记录

- 排版约束从 Skill 提示词和多个阶段私有估算中上收到单一确定性 text-fit 合同；Skill 只保留结果、责任和编辑性边界。
- Planning Review target 改由状态机单一映射派生；上游修订与 downstream draft invalidation 纳入原子 graph transaction。
- Seed/Specs 宿主请求携带 backend contract；editable diagram 与 raster 资产解耦；Preflight 聚合 adapter 准入问题。
- Artifact Tool 启动前写 started receipt，并在 success/failure/timeout 闭合；doctor/preflight/render 复用同一 runtime resolver。
- 表格 adapter 改为内容加权列宽、需求行高与显式边距；相同容量算法在 Python Preflight 和 JavaScript sidecar 双端执行。旧案例预检先识别 S-002/S-007/S-008 风险，再经正式 P5B 提案扩大主表区域，避免针对单页试像素。

### 真实目标验收

- 技术稳定性：通过。旧失败案例的候选 PPTX 生成、PowerPoint 打开、8 页逐页放映、PowerPoint PDF 导出与 8 页 PDF 重渲染均完成；无修复弹窗、裁切、碰撞、缺字或表格越界。
- 故障样本审美：不通过。用户明确拒绝该 candidate；它只能作为故障链路和几何修复证据，不能代表产品视觉基线，也不再被错误地用作稳定性 Issue 的关闭条件。
- 既有视觉基线：通过。用户此前认可的 YU7 正式 Host Create 案例由当前代码隔离重放并完成 12 页真实 PowerPoint 审阅；11 页程序输出不变，S-011 表格为预期改善，未发现 Critical/Major 视觉回归。
- 责任边界：故障样本的审美问题留在其 P6/P5B 工件，不泛化为 renderer 或本稳定性 Issue；只有跨案例复现后才另立通用视觉质量 Issue。
