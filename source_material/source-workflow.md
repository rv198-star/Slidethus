# 原作者工作流与核心思路

## 一句话概括

这套方案不是“主题 → 套模板 → 导出”，而是把专业 PPT 团队的分工拆成连续的 Agent 阶段：

**需求调研 → 资料搜集 → 大纲策划 → 页面策划稿 → 视觉设计稿 → SVG 输出/导入 PPT**

## 四个方法论章节

### 1. 从提问开始，而不是立即生成

先做背景调研，再询问“为谁做、做什么、达到什么目的”等关键问题；需求确认后才生成大纲。大纲使用“数字便利贴”呈现，每页作为一个可调整的结构单元。

### 2. 围绕大纲逐页检索资料

大纲只是骨架。方案按页面标题拆分检索任务，汇总真实、准确的材料，再进入内容和页面规划。原作者项目使用搜索接口；DIY 建议中使用 Grok。

### 3. 在内容与设计之间加入“策划稿”

先生成低装饰的页面草稿，明确每页信息区块、元素位置、图表/图片占位和版式结构；再进行风格化设计。这样把“信息设计”和“视觉设计”拆成两个阶段。

### 4. 用 Bento Grid 作为可计算的页面语言

用不同尺寸卡片组织信息，并通过卡片面积、位置和留白表达层级。原作者认为这种语言同时具备高信息容量、布局灵活性和模型可理解性。

## 作者公开的产出协议

- 大纲：使用固定 JSON 结构，并以 `[PPT_OUTLINE]` 标签包裹。
- 单页设计：以 `1280×720` SVG 为输出画布。
- 视觉布局：Bento Grid / 卡片式布局。
- 使用方式：SVG 代码生成后，可作为整页矢量内容导入 PPT 或设计软件。

## 这份素材实际公开了什么

1. 产品级工作流叙事与若干界面截图。
2. 一个大纲结构 Prompt。
3. 一段 Bento Grid 布局规则。
4. 一个把文字转成单页 SVG 的基础 Prompt。
5. 结果页、需求调研、检索、策划稿、设计稿和 SVG 代码示例。

## 没有公开什么

- 需求调研 Agent 的完整 Prompt 与状态机。
- 检索任务拆分、引用、去重、可信度和事实校验规则。
- 页面策划稿的完整 Schema/Prompt。
- 多页主题一致性、颜色/字体/组件 Token 的生成与约束。
- 图片检索、图片生成、图标、图表与数据绑定策略。
- SVG 语法校验、文本溢出、碰撞检测、自动修复和回归测试。
- SVG 到 PPTX 的完整转换与细粒度可编辑实现。
- 多页并行生成、失败重试、成本控制与质量审计。
