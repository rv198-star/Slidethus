# 为什么先做纵向 MVP

只有接口和 Schema 时，工程仍无法证明用户能够拿到真实演示文件。首个 MVP 应先贯通输入、证据、叙事、页面规划、渲染和交付，再逐步替换更强的实现。

## Interface 与 MinimalImpl

- 接口稳定阶段之间的输入输出。
- MinimalImpl 必须产生真实制品，不能返回空对象或虚构完成状态。
- 后续 ProductionImpl 应能在不改变语义 Artifact 的前提下替换。

## 质量边界

- 所有事实性内容绑定用户来源。
- 页面规划不能被最终渲染绕过。
- 未完成独立 Office 预览时，不把 PPTX 描述为视觉验收通过。
