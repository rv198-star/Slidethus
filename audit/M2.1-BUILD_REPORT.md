# M2.1 Build Report — Ingestion Core

## Objective

Replace the MVP-only in-memory text parser with a provider-neutral, recoverable Production ingestion core without changing M1 Artifact Runtime, weakening Gates or claiming the remaining M2 research/evidence work.

## Implemented behavior

### Parser contract and admission

- `SourceParseRequest`, `SourceParseLimits`, `DetectedSourceFormat`, `SourceParseResult` and `SourceRisk` are explicit DTOs.
- `SourceParser` declares name, version, priority, support and parse behavior.
- `ParserRegistry` selects one admitted parser, rejects unsupported formats and blocks equal-priority ambiguity.
- Format detection uses signatures before suffixes and handles Markdown, TXT, UTF-16 BOM, HTML, PDF, OOXML containers, images, CSV/TSV and unknown data without claiming unsupported parsing.
- The M2.1 Production adapter admits Markdown/TXT and extensionless plain text only.

### Stable source facts

- Chunks have stable source-scoped IDs, ordinals, content hashes, kinds and metadata.
- Markdown sections retain heading context; plain text uses paragraph spans.
- Oversized lines receive unique character-range locators.
- Parser source hash, byte count and text derive from the same captured payload.
- Title and body are scanned for prompt-injection wording, active-content markers and external links; findings are records and never execute.

### Immutable snapshots and Source Ledger lineage

- `source_snapshot.schema.json` validates parser lineage, detected format, limits, Chunks, warnings and risks.
- Snapshots are published at `.slidethus/cache/ingestion/<input-key>.json` with create-if-absent semantics.
- The input key binds source ID, source bytes, parser name/version, detected format and limits.
- Source Ledger records snapshot path/hash, parser, format, limits and counts.
- Workspace validation recomputes file hash, input key, Chunk hashes/IDs, risk IDs and Ledger-reference invariants.
- Snapshot publication precedes the journaled Source Ledger transaction. A failed Ledger commit leaves a safe unreferenced cache entry that can be verified and reused.

### Identity, policy and application integration

- Source IDs cannot be rebound to another file and a path cannot receive an alias ID.
- Unchanged bytes reuse a verified snapshot without creating a Ledger version.
- Explicit title/ownership/confidentiality/authority/allowed-use changes version the Ledger while retaining the snapshot.
- Changed bytes, parser versions or parse limits produce a new snapshot.
- `slidethus source ingest/show` exposes the production path and limits.
- `slidethus mvp` now consumes the same ingestion service, while Evidence、Narrative、Planning and Rendering remain explicit MinimalImpls.

## Compatibility and migration

- Existing M0/MVP Source Ledger records without `ingestion` remain Schema-valid.
- New production-parsed records use `sha256:` content hashes and must reference a valid snapshot.
- `PlainTextSourceParser` remains as a compatibility class over the new text parser contract.
- No new production dependency, provider SDK or network access was introduced.
