# M6.2 Review Round A — Operational Controls

## Review rule

This round used open issue mining without scores. It reviewed the M6 workflow operational layer for interruption/recovery, cache truthfulness, resource budgets, concurrency, structured observability and tamper resistance. M2–M5 semantic/render/review truth remained frozen.

## Initial result

```text
Critical: 0
Major:    6
Minor:    2
Waivers:  0
```

## Major findings and root fixes

### M6.2-A-MAJ-001 — Workflow attempts had no durable start/terminal lifecycle

- Risk: a process could disappear between workflow admission and WOP publication with no durable evidence of an interrupted attempt.
- Root fix: introduced `WAT-*` attempts and immutable `WEV-*` started/terminal events under `.slidethus/workflows/events/`.
- Evidence: orphan-attempt recovery test and WEV tamper control.

### M6.2-A-MAJ-002 — Recovery recorded interruption but Create/Rebuild could not resume an advanced workspace

- Risk: a recovered Create/Rebuild attempt would immediately fail the ordinary stage-0 admission rule even when the same request had legitimately advanced before process death.
- Root fix: non-stage-0 resume is admitted only for an orphan attempt recovered under the current lease with the same workflow/request/execution signature. Ordinary reuse remains rejected.
- Evidence: explicit resume-admission control plus orphan recovery control.

### M6.2-A-MAJ-003 — Cache lookup trusted raw Workflow Operation metadata

- Risk: a tampered WOP could influence cache admission even though workspace validation would later reject it.
- Root fix: cache lookup now validates WOP identity, WFR reference, metrics/status agreement and WEV terminal lineage before considering TTL/currentness.
- Evidence: WOP tamper now invalidates the workspace and subsequent workflow execution fails closed.

### M6.2-A-MAJ-004 — WOP metrics were self-reported rather than cross-checked

- Risk: action/output/change counts could drift from the bound Workflow Application Report without detection.
- Root fix: WOP reference validation recomputes workflow/request/status and action/output/changed-artifact counts from the linked WFR and verifies the terminal event type.

### M6.2-A-MAJ-005 — Runtime budget exhaustion could escape as a bare exception

- Risk: wall-time/provider-cost exhaustion produced an exception instead of an inspectable product outcome.
- Root fix: stage-bound budget exhaustion is converted to blocked WFR/WOP with explicit blocker codes and terminal `blocked` events.
- Evidence: measured provider-cost and wall-time controls PASS.

### M6.2-A-MAJ-006 — Input-byte budget excluded structured request payloads

- Risk: a very large Brief/Revise patch could bypass `max_input_bytes` because only source-file bytes were counted.
- Root fix: input bytes now equal source-file bytes plus canonical structured request payload bytes.
- Evidence: oversized slide-patch admission blocks before Outline mutation.

## Minor findings and fixes

### M6.2-A-MIN-001 — Cache currentness had no explicit age policy

Added `max_cache_age_seconds` (0 disables reuse; maximum 30 days). Cache still additionally requires current artifact bindings and output hashes.

### M6.2-A-MIN-002 — Corrupt or timezone-less operation timestamps could disrupt cache scanning

Cache timestamp parsing now fails closed and skips invalid entries instead of allowing malformed historical metadata to break cache admission.
