# M6.5 Review Round A — License & Third-party Policy

## Review rule

Round A was performed without scores. It reviewed project licensing, release metadata, source-material rights boundaries, Python/Node dependency notices, Plugin/wheel contents, fonts/assets/models, SBOM generation and provenance-manifest integrity.

## Major findings and root fixes

### M6.5-A-MAJ-001 — Project license was intentionally unresolved

- Risk: public users had no explicit grant to use/modify/distribute Slidethus project-owned work.
- Root fix: Apache-2.0 `LICENSE` added; `pyproject.toml` now declares `license = "Apache-2.0"` and license files.
- Verification: Python 3.11 wheel metadata records `License-Expression: Apache-2.0` and all three license/notice files.

### M6.5-A-MAJ-002 — Top-level licensing could be misread as relicensing source material

- Risk: `source_material/` contains user-provided/third-party provenance, excerpts and source-preserved prompts.
- Root fix: `source_material/LICENSE.md`, `NOTICE.md` and machine-readable rights policy explicitly exclude that directory from the project grant. Default wheel/Plugin exclude it.
- Verification: M6.5 Gate `source_material_exclusion` PASS; Plugin inspection contains no `source_material/` path.

### M6.5-A-MAJ-003 — Plugin/wheel did not carry the release rights surface

- Risk: a distributable Plugin could be separated from the repository and lose LICENSE/NOTICE/rights context.
- Root fix: wheel installs LICENSE/NOTICE/THIRD_PARTY/rights policy under release data; Plugin embeds those plus generated SPDX SBOM.
- Verification: Distribution tests 5/5 PASS; clean wheel → clean venv → `slidethus plugin build` produced a 71-file bundle with all required release files.

### M6.5-A-MAJ-004 — No machine-readable release rights policy

- Risk: fonts/assets/models/prepared caches could rely on prose interpretation only.
- Root fix: `release/rights-policy.json` + Draft 2020-12 schema define project-owned scopes, exclusions and redistribution defaults.
- Verification: M6.5 Gate `rights_policy` PASS.

### M6.5-A-MAJ-005 — Dependency graph lacked release SBOM evidence

- Risk: Node transitive dependency/license drift could be invisible even with a lockfile.
- Root fix: deterministic SPDX 2.3 builder records six Python direct dependency constraints and all exact Node lock packages with declared licenses/integrity metadata. Plugin embeds generated SBOM.
- Verification: M6.5 Gate records 6 Python direct + 36 exact Node packages and preserves `@resvg/resvg-js` MPL-2.0.

### M6.5-A-MAJ-006 — Plugin Manifest rejected release-compliance files

- Risk: the schema-backed Plugin boundary originally allowed only Skill/renderer/schema paths, so adding LICENSE/NOTICE/SBOM correctly failed manifest admission.
- Root fix: Plugin Manifest path admission now explicitly includes only top-level LICENSE/NOTICE files and `release/` in addition to the original roots; arbitrary paths remain rejected.
- Verification: Plugin reproducibility and manifest tests PASS.

## Minor findings and fixes

### M6.5-A-MIN-001 — Source provenance manifest drift after rights clarification

`source_material/README.md` changed and `LICENSE.md` was added. `source_material/manifest.json` was updated with both exact hashes/byte counts; source-manifest audit PASS.

### M6.5-A-MIN-002 — Old documentation still said the project license was undecided

README, source-material README and decisions/non-goals now use the Apache-2.0 + explicit external-rights boundary.
