# M2.6 Build Report — Application Orchestration, Capability Degradation, and Security Integration

## Objective

Connect M2.1–M2.5 through one honest application boundary without adding a vendor dependency, bypassing Artifact Runtime, executing unapproved external disclosure or pretending M2 can generate M3 planning artifacts.

## Integrated application path

```text
resolved Project Brief
  → requested/current Source budgets
  → safe multi-format ingestion
  → high-risk Source isolation
  → Source-backed Evidence adjudication
  → orientation Research or explicit user-material completion/waiver
  → current G1/G2
  → optional existing Narrative/Outline revalidation
  → targeted Research/user-material review
  → block Evidence Gap Report
  → current G5A or formal EVIDENCE_READY rework
  → immutable M2 Application Report
```

## Capability and degradation model

| Brief / host state | Application decision |
|---|---|
| External research disabled | user-material mode, M2-level D3 |
| Provider injected + disclosure approved | full M2 research mode, M2-level D0 |
| External research required, capability/approval absent | D5 blocked by default |
| Explicit degradation, no freshness requirement | waived user-material orientation, D3 |
| Freshness-constrained research without provider | D5 blocked |

The M2-level delivery label is operational scope, not final deck Delivery Manifest readiness.

## Security controls

- Provider injection and external-disclosure approval are separate.
- CLI bundles no online provider, SDK, credentials or implicit network behavior.
- High-severity Source risks remain inventoried but are excluded from automatic Evidence by default.
- Source instructions are never executed, including when the caller explicitly allows Evidence promotion.
- Requested/current Source count and bytes are bounded; parser and Research limits remain active.
- Post-preflight file changes rebind the report to the Source bytes actually captured by ingestion.

## M2 Application Report

Reports are published under:

```text
.slidethus/m2/runs/<content-hash>.json
```

They bind:

- Project Brief and current/historical semantic artifact versions/hashes;
- a Project State revision and final phase;
- requested Source fingerprints and config hash;
- provider/capability/disclosure/degradation decisions;
- action-stage results, blockers and warnings;
- Source/Evidence/Research/Gap outputs;
- current M2 Gate evaluations.

Reports are non-catalog runtime facts and are not Delivery Manifests.

## CLI

```bash
slidethus m2 run <workspace> [--source <file> ...]
slidethus m2 run <workspace> --allow-research-degraded
slidethus m2 list <workspace>
slidethus m2 show <workspace> M2R-XXXXXXXXXXXXXXXX
slidethus m2 gate <workspace>
```

The CLI intentionally cannot execute online research. Python callers inject `ResearchProvider` and separately approve disclosure.
