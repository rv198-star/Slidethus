# M2.2 Build Report — Multi-format Source Adapters

## Objective

Extend the M2.1 Production ingestion boundary from Markdown/TXT to the source formats needed by presentation engineering while preserving one provider-neutral protocol, one immutable Snapshot model, one Source Ledger lineage and fail-closed safety.

## Implemented adapters

| Adapter | Extracted facts and locators | Explicit boundary |
|---|---|---|
| Markdown/TXT | sections, paragraphs, lines and character ranges | Unicode text only |
| HTML | title, semantic blocks, table rows, image alt and link targets | scripts/styles/templates ignored and never executed |
| CSV/TSV | logical rows, physical line ranges, inferred header contract | formula-like text preserved, never evaluated |
| PDF | page text | encrypted/empty-text PDF fails; no OCR; forms/annotations/media are partial |
| DOCX | document-order paragraphs/tables, headers/footers and their tables, textboxes, image alt | images, comments, notes, equations, charts/SmartArt and embeddings are partial |
| PPTX | slide/shape/group text, tables, chart category/series cache, notes, image metadata | images, comments, SmartArt, audio/video and embedded objects are partial |
| XLSX | sheet/row/cell coordinates, formulas, hidden-sheet state, raw values and number formats | no calculation; comments/charts/media are partial |
| Raster image | format, dimensions, mode, frames, metadata keys and limited EXIF text | metadata-only partial; no OCR or visual understanding |

Supported raster signatures are PNG、JPEG、GIF、WebP、BMP、TIFF and ICO. SVG, legacy OLE, macro-enabled OOXML, encrypted PDF and unknown families remain unsupported.

## Shared safety and lineage

- Every adapter implements `SourceParser` and returns `SourceParseResult`.
- `SourceParseLimits` bounds bytes, Chunks, risks, pages, slides, sheets, rows, cells, ZIP entries, one ZIP member, total decoded/expanded bytes and total image pixels.
- OOXML preflight rejects duplicate/case-colliding names, path escape, drive paths, symlinks, encryption, macros, DTD/entities and resource expansion before a document library opens the package.
- External relationships, formulas, active content, embedded objects and sensitive EXIF are recorded but never executed or fetched.
- Parser selection is revalidated against the adapter's captured payload, and source bytes are re-fingerprinted after parsing; a format/content change publishes neither Snapshot nor Ledger version.
- All formats use M2.1 input-keyed create-if-absent immutable snapshots and Artifact Runtime Source Ledger transactions.
- `parsed` and `partial` are persisted in both Snapshot and Ledger and cross-validated.
- A successful result must contain admitted facts; metadata-only or incompletely interpreted formats are partial, while empty/unusable inputs fail.

## Optional capability model

`slidethus[ingestion]` installs:

- `pypdf>=5,<7`;
- `python-docx>=1.1,<2`;
- `openpyxl>=3.1,<4`;
- `Pillow>=10,<13`.

HTML and CSV use the standard library; PPTX reuses the base `python-pptx` dependency. Missing optional dependencies raise `SourceCapabilityError`. `slidethus doctor` reports optional adapter availability without making it a base-install failure.

## Application integration

- `slidethus source ingest/show` uses the complete Registry and exposes all format-native limits.
- The complete MVP now uses the same default Registry instead of a hidden text-only registry.
- Explicitly injected parsers remain supported for bounded tests and custom adapters.
- A CSV fixture now reaches the complete G0–G9 MVP while its Minimal Evidence remains bound only to the admitted source Chunks.

## Remaining scope

M2.2 intentionally does not implement:

1. OCR or image semantic understanding;
2. audio/video interpretation;
3. Office formula evaluation or embedded-object execution;
4. Web research and query/task lineage;
5. Evidence normalization, deduplication, conflict, authority or freshness;
6. block-level evidence binding and outline-driven evidence rework.

These boundaries are recorded in Source warnings/partial status, Skill behavior and documentation. The next implementation module is M2.3 Research Planning/Runtime.
