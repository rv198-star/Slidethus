# M2.4 Build Report — Deterministic Evidence Engine

## Objective

Convert current Production Source facts and M2.3 Research Results into a versioned Evidence Ledger with stable identity, exact deterministic deduplication, source/candidate lineage, support/conflict/freshness/authority decisions and fail-closed use policy.

## Implemented path

```text
Production Source Chunk
  → conservative EvidenceCandidate
  → exact claim identity
  → policy adjudication
  → versioned Evidence Ledger

Research Result
  → materializer-owned partial Web Source Snapshot
  → indirect EvidenceCandidate
  → provisional/qualified Evidence
  → semantic research-cycle completion
```

## Core contracts

### Claim and Candidate identity

- `normalize_claim` removes presentation variation but preserves percentages, units, ratios, decimal punctuation, unary signs and numeric ranges.
- Only exact normalized claims merge automatically.
- Candidate identity binds Source/locator/support/origin/Chunk, Research Run/Result and explicit conflict facts.
- Production claims persist `candidate_bindings` so current decisions can be independently reconstructed.
- Existing `EVD-*` remain assigned to the same claim key; new claim keys receive the next ID.

### Source binding

Production Source refs contain:

- `source_id`;
- format-native `locator`;
- stable `chunk_id`;
- Chunk `content_hash`;
- support type.

A Source update may commit, but downstream Evidence becomes draft and G2 fails until re-adjudication. Old Evidence IDs are retained and downgraded rather than silently reused for replacement facts.

### Research Result materialization

- Only credential-free HTTP(S) URLs are admitted.
- Scheme, host and default ports normalize; query parameters remain; fragments are removed.
- A canonical URL maps to one materializer-owned Web Source ID.
- Distinct `RSLT-*` records from different Runs/providers remain separate Chunks; refresh replaces only the same result identity.
- Web Source Snapshot status is always `partial` and records `remote_body_fetched=false`.
- The Source content hash identifies materialized provider payload, not the remote page body.
- Another ingestion/fetch owner's Web Source is never overwritten.

### Adjudication

- opposing explicit stances → `disputed` and `do_not_use` for every current group member;
- no current support → `unsupported`;
- explicit inference/assumption remains qualified;
- direct fully parsed non-Web support may be `verified`;
- indirect or partial support is `provisional`;
- stale/unknown freshness and low authority require qualification;
- metadata-only/do-not-use Sources fail closed;
- all decisions carry reason codes.

### Cycle completion

A semantic orientation/targeted cycle completes only after every referenced Run is complete, every result is materialized and every result has current non-blocked Evidence. Completion unions Run/Source IDs, aggregates query count and does not create a new artifact version when repeated unchanged.

## Failure and degraded paths

- malformed/credentialed URL → materialization failure;
- incomplete/tampered Research Run/Cache → failure before Source publication;
- another Web Source owner at canonical URL → fail closed;
- stale Candidate/Chunk binding → rejected or downgraded;
- concurrent Ledger writer → `ArtifactConflictError`;
- unsupported/disputed/forbidden Evidence → `do_not_use`;
- provider summary without fetched body → provisional/qualified, never verified;
- cycle with missing materialization/adjudication → remains incomplete;
- external research unavailable → M2.3 offline blocked; M2.4 creates no fabricated result.

## Explicit non-goals

M2.4 does not provide:

1. LLM claim extraction or paraphrase clustering;
2. fuzzy semantic deduplication or contradiction inference;
3. production Web search/fetch vendor adapters;
4. remote page-body verification;
5. block-level binding/gap routing;
6. automatic Narrative/Slide generation.
