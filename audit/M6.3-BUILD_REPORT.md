# M6.3 Build Report — Plugin Packaging

## Outcome

M6.3 turns Slidethus from a repository-bound implementation into a technically distributable package boundary:

- Python wheel carries the canonical Skill/workflow and renderer source;
- Plugin ZIP is deterministic and schema-backed;
- Skill installation is explicit and non-destructive;
- renderer dependency bootstrap is explicit, pinned, content-addressed and tamper-evident;
- installed mode works outside the Git checkout.

**M6.3 Submodule Gate: PASS.**

## Delivered

### Wheel-installed distribution assets

`pyproject.toml` installs canonical repository files into:

```text
share/slidethus/skill/
share/slidethus/renderer/
```

No second maintained source copy is introduced.

### Plugin distribution API/CLI

`src/slidethus/distribution.py` and CLI now provide:

```text
slidethus plugin status
slidethus plugin build <output.zip>
slidethus plugin install-skill <host-root>
slidethus plugin bootstrap-renderer
```

### Deterministic Plugin bundle

Bundle includes:

- complete `.agents/skills/slidethus/**` tree;
- packaged Schemas;
- renderer runtime source;
- schema-valid `plugin-manifest.json` with stable `PLG-*` identity and exact file hashes.

The ZIP uses fixed metadata/stored entries and refuses to overwrite a different existing file.

### Managed renderer bootstrap/cache

Bootstrap verifies:

- renderer package + lock exact pins;
- Node >=20;
- npm >=9;
- clean `npm ci --omit=dev --ignore-scripts --no-audit --no-fund`;
- required direct dependencies;
- complete renderer-source digest;
- complete installed dependency-tree digest/count;
- internal-only relative npm symlinks.

The prepared cache is reused only if all source/dependency bytes still match the recorded identity.
