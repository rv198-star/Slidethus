## Major findings and root fixes

### M6.1-A-MAJ-001 — Workflow names existed only as Skill documentation

- Risk: Create/Rebuild/Improve/Audit/Revise/Extract Style could be described without a shared runtime truth.
- Root fix: added one `WorkflowApplicationService`, immutable `WFR-*` report contract, workspace validation, and `workflow run/list/show` CLI. Workflows orchestrate existing M2–M5 services rather than private state machines.

### M6.1-A-MAJ-002 — M3 claimed automatic repairs that had no executor

- Risk: `outline_timing_mismatch`, `bento_overuse` and `repetitive_layout_rhythm` were labeled automatic while `PlanningRepairService` only implements `headline_too_long`, creating guaranteed blocked “automatic” attempts.
- Root fix: those findings are now `assisted`. Automatic declaration again matches executable capability.
- Evidence: Rebuild PPTX path reaches M3 ready after the correction; M3 Exit remains 13/13 PASS.

### M6.1-A-MAJ-003 — M3 ready state contradicted Minor-only Planning Review semantics

- Risk: M3 orchestration intentionally allows Minor-only review findings with warning, but report reference validation required `review.status=pass`, rejecting valid ready runs.
- Root fix: ready M3 reports now require zero Critical/Major; Minor-only `issues` status is accepted and remains visible.

### M6.1-A-MAJ-004 — Historical downstream facts blocked legitimate upstream rework

- Risk: after an Outline change invalidated Render/Quality/M5 artifacts, validators still demanded those historical facts match current upstream versions, making Revise impossible.
- Root fix: currentness is enforced only when the corresponding artifact is active/current. Historical Render/Quality/M5 facts remain immutable and tamper-checked but no longer block upstream transactions.
- Evidence: focused M5 invalidation test PASS; full Revise path updates target slide, regenerates downstream, returns G8 PASS and a valid workspace.

### M6.1-A-MAJ-005 — `auto_repair=False` did not cover semantic/visual Repair Execution

- Risk: Audit could call M5 with automatic repair disabled yet still execute a semantic/visual Repair Plan.
- Root fix: M5 now retains the immutable Repair Plan and records `review_repair: skipped`; no Repair Execution occurs when `auto_repair=False`.
- Evidence: Major semantic issue negative control confirms no repair report and zero frozen-artifact mutation.

### M6.1-A-MAJ-006 — Rebuild needed explicit original-file preservation

- Risk: productization could accidentally treat the original deck as an output target.
- Root fix: Rebuild binds input hashes and verifies source bytes are unchanged after the complete M3→M4→M5 chain. Outputs are always under the new workspace.
- Evidence: real PPTX Rebuild integration PASS with byte-identical source.

## Minor findings and root fixes

### M6.1-A-MIN-001 — Extract Style provenance/rights were implicit

The candidate now records reference filename/SHA and `rights_status=reference_only` inside admitted `shape_rules`, and explicitly forbids copying unlicensed font/brand bytes or pixel-template locking.

### M6.1-A-MIN-002 — Workflow operational facts lacked tamper enforcement

`WFR-*` facts are now content-addressed, validated from `.slidethus/workflows/runs/`, bind historical/current artifact versions and output hashes, and fail workspace validation after tampering.
