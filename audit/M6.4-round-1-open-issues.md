# M6.4 Review Round A — Examples & Evaluation

## Review rule

Round A was performed without scores. It reviewed the six-workflow evaluation corpus, compatibility claims, executable examples, quick/Production execution strategy and the interaction between M6.2 operational facts and long-running Production workflow tests.

```text
Critical: 0

```

## Major findings and root fixes

### M6.4-A-MAJ-001 — Product workflows had no executable six-case corpus

- Risk: README/Skill named six workflows, but release evidence was spread across tests and milestone prose.
- Root fix: `evals/m6/suite.json` now defines exactly one canonical case for Create/Rebuild/Improve/Audit/Revise/Extract Style, including expected status/Gate, invariants, execution tier and concrete pytest selector.
- Verification: M6.4 persistent Gate confirms six unique workflow cases and valid selectors.

### M6.4-A-MAJ-002 — Compatibility claims were prose-only

- Risk: Python/Node/Office/provider/platform statements could drift independently across docs.
- Root fix: `docs/compatibility-matrix.json` plus Draft 2020-12 schema records capability and platform status in machine-readable form. Unverified platforms are not promoted to tested status.
- Verification: M6.4 persistent Gate validates 7 capability rows and 4 platform rows.

### M6.4-A-MAJ-003 — One monolithic Production eval exceeded bounded execution windows

- Risk: grouping Create/Rebuild/Revise real M3→M4→M5 paths into one command can exceed a bounded tool invocation, producing timeout noise rather than quality evidence.
- Root fix: ADR-0024 formalizes `quick` versus `production`; Production selectors may run in bounded non-overlapping groups while the corpus selector set remains fixed.
- Verification: Create/Audit/Improve 3/3 PASS; Rebuild/Extract Style 2/2 PASS; Revise executed against a persisted Create baseline and returned G8 PASS with a valid workspace.

### M6.4-A-MAJ-004 — Open workflow attempt facts invalidated the workflow that created them

- Risk: M6.2 `started` events were initially treated as invalid until a terminal event existed. Nested M3/M4 Artifact Runtime validation therefore rejected a legitimately running workflow.
- Root fix: one valid `started` event without terminal is now a legal open operational attempt. The next exclusive lease recovers an orphaned open attempt before new work. Event tampering and invalid sequences still fail closed.
- Verification: focused recovery controls 3/3 PASS and Create/Audit/Improve Production group returned 3/3 PASS after the fix.

## Minor findings and fixes

### M6.4-A-MIN-001 — README referenced an eval directory that did not exist as a product corpus

The repository now contains `evals/m6/`, executable examples under `examples/workflows/`, installation/workflow documentation and evaluation/compatibility documentation.

### M6.4-A-MIN-002 — Quick evaluation could be confused with full Production certification

The runner and docs now state that quick mode validates all corpus declarations but executes only cases marked `quick`. Production renderer/G8 evidence is a separate release-quality tier.
