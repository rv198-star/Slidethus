# M2.5 Review Round A — Open Issue Mining

## Scope

This review evaluated block-level Evidence binding, gap analysis, targeted-query handoff, semantic targeted-cycle completion, G5A and formal P2 rework without scores. It inspected current-version inputs, stable report identity, explicit factual requirements, policy/qualification checks, Research Plan lineage, rework transaction semantics, history validation and legacy compatibility.

LLM factuality classification, automatic research execution, Narrative/Slide generation and visual design were excluded because they are explicit non-goals.

## Findings

### Critical

None.

### Major — G5A originally proved only that a targeted cycle existed

- Problem: the old G5A checked Slide Specs presence and a current-outline targeted cycle, but not whether required slides/blocks had known, usable, properly qualified Evidence.
- Root fix: current-version G5A now recomputes deterministic binding rules for explicit/factual slide and block types, unknown/blocked Evidence and required qualifications. It also requires current G2 lineage.
- Verification: missing required block, unknown/blocked Evidence, absent qualification and required slide-to-block coverage fail G5A.

### Major — arbitrary text could have been misclassified as factual by heuristics

- Problem: broad keyword or numeric heuristics would make the deterministic core claim semantic understanding it does not have and produce unstable false blockers.
- Root fix: schemas admit explicit `evidence_requirement`; defaults are restricted to deterministic slide/block types. Other content remains optional unless explicitly declared.
- Verification: legacy MVP artifacts remain valid while explicit required blocks fail closed.

### Major — gap reports initially omitted Brief and Source inventory lineage

- Problem: report identity bound Evidence/Outline/Specs but query suggestions depend on Brief policy, and Evidence authority/use semantics depend on current Source inventory. Brief/Source changes could leave a report appearing current.
- Root fix: immutable reports bind Project Brief, Source Ledger, Evidence Ledger, Deck Outline and optional Slide Specs artifact versions/content hashes.
- Verification: current and historical artifact refs are independently validated; route/completion reject changed inputs.

### Major — report issue/query identities were not independently recomputable

- Problem: a manually rewritten report could change issue/query IDs and references while recomputing only the outer report hash.
- Root fix: issue IDs derive from code/slide/block/evidence/earliest-phase facts; query IDs derive from slide/block/query/reason/outline version. Workspace validation recomputes both, property-to-artifact type and report ID/file key.
- Verification: tampered reports fail `invalid_evidence_gap_report`.

### Major — user-material targeted completion could race current artifacts

- Problem: analysis and semantic cycle write originally used separate graph observations. Concurrent Brief/Source/Evidence/Outline/Specs changes could complete a cycle from stale bindings.
- Root fix: the report captures all input versions; completion re-reads one locked graph, compares every input ref, requires passing G2/current Slide Specs, and writes Evidence with the captured optimistic-lock version.
- Verification: changed report inputs fail before completion; Artifact Runtime still arbitrates concurrent Evidence writes.

### Major — user-material completion could silently absorb Web or existing Run lineage

- Problem: a convenience path could mark a Web-backed or already researched cycle as `user_materials`, clear/under-count queries, or bypass Result materialization.
- Root fix: user-material completion rejects Web-backed Sources and any existing Run lineage. Web/Run cycles must complete through M2.4 Evidence Engine. Gap-free user-source cycles remain offline-capable with query_count=0.
- Verification: Web-backed completion fails; user-material completion is idempotent and passes G5A after current binding checks.

### Major — required slide Evidence could remain unbound or unqualified at block level

- Problem: slide-level IDs alone did not prove which page block carried a claim; a provisional/inference claim could enter a required factual slide without qualification.
- Root fix: required slide Evidence must reach at least one block; required block IDs must be declared by the Outline; qualified Evidence on required slide/block needs `evidence_qualification`.
- Verification: missing coverage and qualification fail report/G5A; adding explicit qualification passes.

### Major — gap query handoff could reference stale or unknown slides

- Problem: an explicit query helper accepted syntactically valid slide IDs without verifying the current active Outline.
- Root fix: M2.3 `plan_explicit_targeted_research` validates every supplied slide against the registered current Outline and preserves outline version/cycle identity.
- Verification: `S-999` fails before plan creation; stable current suggestions produce stable Plan IDs.

### Major — rework transition was not a fully auditable optimistic transaction

- Problem: a backward phase change could have discarded its reason or routed from a stale report after another artifact version changed.
- Root fix: Artifact Runtime `route_rework` validates expected artifact versions under lock, writes an authoritative Decision Log entry and summary, keeps only Gates admitted by `EVIDENCE_READY`, marks Narrative and later artifacts draft, and histories Project State transactionally.
- Verification: stale report versions raise `ArtifactConflictError`; accepted rework preserves G0–G2 and records rationale.

### Minor — Gap Report advertised a `blocked` state it never produced

- Problem: runtime validation only admitted pass/gaps semantics while Schema also advertised blocked.
- Root fix: Schema now exposes only implemented states.

### Minor — historical reports needed version-aware validation

- Problem: validating only current artifacts would make an immutable historical report invalid after legitimate later edits.
- Root fix: report validation resolves current or Artifact Runtime history versions and checks the referenced content hash.
- Verification: a report remains valid after a later Slide Specs version.

### Minor — legacy Outline/Specs lacked explicit evidence requirement fields

- Problem: making new fields globally required would break existing workspaces and examples.
- Root fix: fields remain optional with conservative deterministic defaults; production workflows are encouraged to write them explicitly.

## Regression evidence

- M2.1–M2.4 Source/Research/Evidence lineage and Gate behavior remain green.
- No network call is introduced by query suggestions or plan construction.
- Gap reports are non-catalog runtime facts and do not mutate semantic artifacts.
- Rework remains a Project State transition, not a new Phase.
- Minimal MVP and example project continue to pass G5A under legacy-compatible defaults.

## Result

- Critical findings: 0.
- Major findings: 9, all root-fixed.
- Minor findings: 3, all fixed.
- Waivers: none.
