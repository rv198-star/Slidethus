# M6.3 Review Round A — Plugin Packaging

## Review rule

This round used open issue mining without scores. It reviewed whether Slidethus can be installed/distributed without a Git checkout, whether Plugin artifacts are reproducible and self-verifying, and whether the Node renderer bootstrap is explicit, pinned and tamper-evident.

## Initial result

```text
Critical: 0
Major:    6
Minor:    2
Waivers:  0
```

## Major findings and root fixes

### M6.3-A-MAJ-001 — Wheel installed Python code/schemas but omitted the canonical Skill and renderer source

- Risk: an installed package could not materialize the product Skill or bootstrap the Production renderer outside the repository checkout.
- Root fix: canonical Skill/workflow and renderer runtime files are installed as `share/slidethus/` data-files; no duplicate authoring copy was created.
- Evidence: clean Python 3.11 wheel/venv install resolves Skill/renderer from the venv share tree outside the repository.

### M6.3-A-MAJ-002 — Renderer discovery assumed repository layout

- Risk: `renderer_root()` defaulted to `find_repository_root()/renderers/pptxgenjs`, making installed mode fail before capability checks.
- Root fix: renderer resolution now supports managed prepared cache, repository source and installed share source while preserving explicit/env overrides.

### M6.3-A-MAJ-003 — Plugin ZIP had no schema-backed stable release manifest

- Risk: a ZIP could contain files without a stable identity or machine-verifiable contents/requirements.
- Root fix: added `plugin_manifest.schema.json`, stable `PLG-*` identity, sorted unique paths, exact file hashes and Python/Node/renderer requirements.

### M6.3-A-MAJ-004 — Prepared renderer cache initially trusted source lock + direct dependency versions only

- Risk: local `node_modules` JavaScript could be modified without changing direct package version metadata.
- Root fix: bootstrap now records a byte-level complete dependency-tree digest/count; prepared-cache admission recomputes it before reuse.
- Evidence: injected dependency-file tamper forces a clean reinstall in tests.

### M6.3-A-MAJ-005 — Renderer cache identity initially covered package-lock but not the complete sidecar source

- Risk: `render.mjs`/`preview.mjs` drift could reuse a cache prepared for different renderer bytes.
- Root fix: cache root now derives from the digest of all canonical renderer runtime files and verifies each cached source file byte-for-byte.

### M6.3-A-MAJ-006 — Renderer dependency installation was not a productized explicit action

- Risk: users had to know the repository-specific `npm ci --prefix ...` command and rendering might otherwise tempt implicit install behavior.
- Root fix: added explicit `slidethus plugin bootstrap-renderer`; rendering itself never installs dependencies. Bootstrap verifies Node>=20/npm>=9, package/lock pins, runs clean `npm ci`, and re-verifies the cache.

## Minor findings and fixes

### M6.3-A-MIN-001 — ZIP compression could introduce unnecessary platform/zlib reproducibility variation

Plugin ZIP now uses fixed timestamps/modes and `ZIP_STORED`; two independent builds are byte-identical in the persistent distribution validator.

### M6.3-A-MIN-002 — Destructive materialization/overwrite behavior needed explicit refusal

Skill install refuses modified/nonmatching target trees and Plugin build refuses to overwrite a different existing output file.

## Additional real-environment correction

The first dependency-tree integrity rule rejected every symlink. Real npm legitimately creates relative `.bin` symlinks. The rule was corrected to hash and admit only relative symlinks resolving inside `node_modules`; absolute/escaping links remain rejected. Real Node 22/npm bootstrap then passed twice with stable source/dependency digests and `changed=true → false`.
