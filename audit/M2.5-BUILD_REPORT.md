# M2.5 Build Report — Block-level Evidence Binding, Gap Analysis, and Rework

## Objective

Prove page-level Evidence readiness before design by connecting current Outline and Slide Spec facts to current policy-bearing Evidence, persisting inspectable gaps, creating bounded targeted-research handoffs and routing unresolved proof gaps back to P2.

## Implemented contracts

### Explicit and conservative requirement model

Outline slides and Slide Spec blocks may declare:

```text
evidence_requirement = required | optional | none
```

Blocks may additionally declare:

```text
evidence_qualification
```

Legacy artifacts remain valid. When a declaration is absent, only unambiguous slide/block types receive deterministic defaults. The runtime does not claim general natural-language factuality classification.

### Current-version binding analysis

`EvidenceBindingService` reads one locked graph snapshot containing:

- Project Brief;
- Source Ledger;
- Evidence Ledger;
- Deck Outline;
- optional Slide Specs;
- Project State and current Gate summaries.

It checks:

- current G2 lineage;
- current-outline targeted cycle;
- required slide/block Evidence presence;
- unknown or policy-blocked Evidence;
- qualification requirements;
- required slide Evidence reaching a responsible block;
- block Evidence being declared by the Outline.

### Evidence Gap Report

The service publishes immutable runtime facts under:

```text
.slidethus/evidence/gaps/<content-key>.json
```

Each report binds Brief/Source/Evidence/Outline/Specs versions and content hashes, stable issue/query IDs, per-slide status, severity, earliest responsible phase, suggested action and rework target. Historical reports remain verifiable against Artifact Runtime history.

### Targeted research handoff

When external research is admitted, blocking gaps produce deterministic query suggestions. `plan_explicit_targeted_research` converts them to the existing M2.3 provider-neutral Research Plan after validating every slide against the current active Outline.

A suggestion or Plan is neither executed research nor Evidence.

### User-material targeted completion

A current-outline targeted cycle may complete without network access only when:

- current G2 passes;
- current Slide Specs exist;
- no blocking binding gaps remain;
- all bound Sources are non-Web;
- no Research Run lineage is present.

The operation is idempotent and records `query_count=0` with `basis=user_materials` or `none_required`.

### Formal rework

`ArtifactRuntime.route_rework` transactionally verifies expected artifact versions, records a Decision Log rationale, preserves admitted G0–G2 summaries, marks downstream artifacts draft, histories Project State and routes only from admitted phases to `EVIDENCE_READY`.
