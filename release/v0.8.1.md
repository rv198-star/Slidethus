# Slidethus v0.8.1

本次是 v0.8.0 之上的视觉基础与决策传播增强；不引入行业模板，不更换渲染器，不扩大为 v1.0 验收。

## 主要变化

- Designed Host Create 在 Outline 后、Slide Specs 前建立不可变 `ArtDirectionSeed`。图片、图表、关系图、表格或排版主导的表达选择提前进入策划，不再只到 P6 才考虑视觉。
- 默认设计路径要求 Taste 驱动可查看的原生视觉样板，记录工作区路径与 SHA-256；缺少或篡改样板会明确阻断，不能静默换成固定配色基线。
- 同一 Seed 贯穿 Slide Specs、Layout 上下文、ArtDirectionPacket 与 Visual System。已明确要求的视觉载体必须落实为语义 Block，表面处理必须在最终页面设计中兑现。
- 逐页规划纯色、色调变化、色块/线框处理或图片主导的节奏；保持统一配色与构图判断，不强制背景图、深色页、图表数量或 Bento 配额。
- 明确区分 `resource-only`、`taste-informed` 和 `taste-generated`。后者仅记录制作路径，不证明审美质量；仍须独立审阅真实 Office 页面。

## 安装与兼容

```bash
python -m pip install slidethus-0.8.1-py3-none-any.whl
slidethus plugin status
slidethus plugin install-skill /absolute/path/to/project
```

Wheel 与资源 ZIP 包含九个技能入口、共享参考、固定 Taste 原文和 Schema。资源 ZIP 不是独立运行程序，也不是 Codex Marketplace 一键安装声明；更新已有技能时遵守安装器冲突保护。

自定义 Host 响应程序需要支持新增 `art_direction_seed` 请求及对应上下文，不应假定 v0.8.0 的五阶段响应序列原样适用。显式 deterministic/legacy baseline 保留原有能力边界，不被自动称为 Taste-generated。

## 验证与已知边界

- 本轮仅 Python 3.11；精确回归、分发与安装验证结果记录在 `plans/v0.8.1-release.md`，skip 不算通过。
- 全量检查首次 370 passed / 43 skipped / 1 failed；唯一失败为收尾时 README 与包版本同步时序，之后该项及整个分发模块重测通过。最终 371 个非跳过用例均有通过结果；Schema/包审计、lint、分发 7/7、Node 5/5、仓库外安装和九技能校验通过。
- YU7 真实任务完成了原生样板、正式规划和 12 页候选，包含实车图片、原生数值图表与版本表；用户认可产出。程序预览不是 Office 预览，本轮未完成其实际 PowerPoint 全篇验收，候选状态不被改写为最终交付通过。官方图片与案例成品不随软件包分发。
- 既有 M3 自动返工遇到需要从 Layout 直达 Narrative 的路径时可能被状态机拒绝；恢复时更改 Brief completion 元数据也可能触发规划 lineage 重建。此类情况需正式重入上游阶段，不能手改 Gate 或复用失效响应。本版未改该既有路由，不声称所有恢复路径均已验证。
- 上述剩余事项记录在 `plans/v0.8.1-follow-up-issues.md`，不作为已完成能力，也不在本次发布中继续扩大修复范围。
- 搜索、模型、图片生成、Artifact Tool 与 Office 渲染仍依赖宿主；缺失时显式暂停或降级。
- 当前是 0.x 能力发布，M6.6 / v1.0 Release Gate 保持未通过。扩大行业/场景验证留作后续真实任务，不作为本轮追加范围。
