# 00｜Product Charter

## 1. 定位

Slidethus 是一套面向通用 Agentic Host 的演示文稿工程 Skill。它把“理解业务目标、研究证据、组织叙事、策划页面、建立视觉系统、渲染、审计和修复”固化为可复用工作流。

它的目标不是替代某个模型或某个 PPT 软件，而是为模型和工具提供一套稳定的专业作业系统。

## 2. 要解决的问题

主流 AI PPT 流程经常把四类问题混在一个提示词里：

1. 内容是否正确；
2. 叙事是否成立；
3. 页面应该怎样组织；
4. 视觉应该怎样呈现。

模型在一次生成中同时承担这些任务时，常见结果是：内容空泛、结构重复、模板感强、事实不可追溯、页面看似完整但无法讲述。

Slidethus 通过分阶段产物降低耦合：每一阶段只解决一种主要问题，并通过 Gate 决定是否进入下一阶段。

## 3. 核心用户

### 3.1 直接用户

- 需要从长文、调研、数据或既有材料生成演示文稿的人；
- 需要重构、改造或审计现有 PPT 的人；
- 需要批量生成课程、咨询方案、汇报、销售材料和研究简报的团队；
- 希望把专业 PPT 方法沉淀为可复用 Skill 的开发者。

### 3.2 运行宿主

- Codex CLI / IDE / 桌面项目；
- ChatGPT 或其他具备文件、搜索、图像、代码与本地工具能力的 Agentic Host；
- 后续通过 Plugin 或自建 Agent Harness 分发的运行环境。

## 4. 用户价值

Slidethus 应让用户获得以下可验证结果：

- 内容与目标、受众和演示场景一致；
- 每页只有明确的核心命题，不是素材堆叠；
- 关键事实可以追溯到来源；
- 页面结构在最终视觉前即可审阅和重排；
- 视觉系统跨页一致，但布局不机械重复；
- 可对单页或局部阶段返工，而不是整套重做；
- 输出明确声明编辑等级和已知限制；
- 失败时能指出缺在哪个阶段、需要补什么，而不是静默生成低质量结果。

## 5. 产品原则

### P1. 内容真相先于视觉表面

视觉不能掩盖缺失、冲突或未经支持的事实。

### P2. 中间产物是事实资产

Project Brief、Evidence Ledger、Deck Outline、Slide Specs、Layout Plans 和 Visual System 都是可版本化资产，不是模型的临时思考。

### P3. 页面策划与视觉设计分离

页面先确定“表达什么、如何组织、放在哪里”，再决定颜色、字体、图片和装饰。

### P4. 语义与渲染解耦

同一套语义资产应支持 SVG、PPTX Native、Hybrid 等不同后端。更换后端不能重写内容事实。

### P5. 先找问题，再评分

开放问题审计先于维度评分。评分不能把 Critical 或 Major 问题平均掉。

### P6. 单主编排器优先

一个主 Skill 管理阶段、状态和 Gate。子代理只承担独立、低冲突、可汇总的任务。

### P7. 提供可解释降级

工具不足时输出可用的阶段成果和缺口说明，不能假装完成完整闭环。

## 6. 任务类型

| Workflow | 说明 | 主要输入 | 主要交付 |
|---|---|---|---|
| Create | 从主题和素材新建 deck | 主题、文件、约束 | 全部中间产物 + deck |
| Rebuild | 从既有 deck 重建逻辑与视觉 | PPTX/PDF/图片 | 重构方案 + 新 deck |
| Improve | 在保留目标的情况下提升现有 deck | deck + 修改目标 | 定点改造版本 |
| Audit | 只做事实、叙事、视觉与交付审计 | deck/中间产物 | 问题清单 + Gate |
| Revise Slide | 修改指定页并做依赖回归 | slide IDs + 反馈 | 局部新版本 |
| Extract Style | 提取现有 deck 的视觉系统 | deck/参考图 | Visual System |

## 7. v0.1 成功标准

本基础阶段的成功标准不是“生成最漂亮的 PPT”，而是：

- 仓库可被本地 Codex 正确理解；
- Skill 可以被自动发现；
- 所有核心中间产物都有 Schema；
- 示例项目可被完整校验；
- 状态迁移和 Gate 有明确合同；
- 页面策划稿可通过确定性灰模渲染验证；
- 后续模型和渲染能力可以通过适配器接入；
- 多轮审计能够定位结构缺口，而不是只给主观评价。

## 8. 非目标

v0.1 不包含：

- 独立 SaaS 产品和可视化编辑器；
- 追求所有场景一次生成成功；
- 通用模型训练或微调；
- 固定搜索供应商或固定图像模型；
- 把所有复杂图形转成完全可编辑的 Office 原生元素；
- 自动绕过版权、品牌或安全限制；
- 默认使用多个代理扮演虚拟团队。

## 9. 核心术语

- **Deck**：完整演示文稿。
- **Slide Message**：该页必须让观众记住的一句话。
- **Evidence**：支持事实性声明的可定位来源记录。
- **Slide Spec**：本页表达目标、内容块和视觉意图，不含最终样式坐标。
- **Layout Plan**：页面策划稿的几何结构与块映射。
- **Visual System**：跨页共享的视觉 Token、规则和禁用模式。
- **Render Backend**：把语义、布局和视觉资产转换成 SVG/PPTX 等格式的实现。
- **Gate**：阶段进入下一步前必须满足的显式条件。
- **Degraded Mode**：宿主工具不足时的受控降级执行方式。
