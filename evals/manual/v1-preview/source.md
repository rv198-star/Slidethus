# 企业 AI Agent 落地：真正该建设什么

## 结论
企业不应把主要精力放在“训练一个更聪明的 Agent”上。通用模型的推理、规划、工具使用能力会由平台公司持续进化；企业真正需要长期沉淀的是让任何合格 Agent 都能调用的数据、知识、业务流程、规则、工具、权限和评价标准。

## 为什么现在很多 Agent 项目效果不稳定
很多项目把主要工程投入放在 Prompt、角色设定、Agent 数量和链路编排上。Demo 阶段看起来聪明，但进入真实业务后，会遇到上下文缺失、数据口径不一致、权限不清、异常流程没人定义、工具不可调用、输出无法评价等问题。问题往往不是 Agent 不够聪明，而是企业没有提供可工作的业务环境。

## 一个更合适的类比
大学负责培养具备通用能力的人才，企业不会要求每个员工入职后重新学习人类通识能力。企业真正提供的是业务数据、制度、SOP、系统权限、工具、岗位责任和绩效标准。AI Agent 也应采用相同思路：平台负责通用智能，企业负责业务可执行环境。

## 企业需要建设的七类基础设施
1. 数据：结构化数据、业务事实、实时状态和统一口径。
2. 知识：产品、客户、案例、制度、经验和历史决策。
3. 流程：标准路径、分支、异常处理、升级和人工接管。
4. 规则：业务约束、风险红线、审批条件和合规要求。
5. 工具：ERP、CRM、浏览器、文件系统、消息系统和内部 API。
6. 权限：谁能看什么、做什么、在什么条件下做。
7. 评价标准：什么叫完成、正确、优质、风险可接受。

## 从单点 Copilot 到业务流水线
第一阶段可以让 AI 帮人完成单个任务，例如写报告、查资料、整理表格；第二阶段让 AI 调用工具，完成跨系统的长流程；第三阶段再考虑多个 Agent 按责任分工协作。顺序应是先把业务环境结构化，再增加自动化程度，而不是先增加 Agent 数量。

## 管理者应该关注的三个问题
第一，这个业务场景的输入、决策、动作和输出是否已经说清楚？第二，Agent 是否拥有完成任务所需的数据、知识、工具和权限？第三，我们是否有可以客观判断成功与失败的评价标准？如果这三个问题无法回答，增加模型能力通常只能改善演示，不能形成稳定生产力。

## 建设顺序
先选一个高频、高价值、边界清晰的业务场景；把现有员工工作过程还原成事实、规则和动作；建立可调用工具和最小权限；定义可验证输出；让单个 Agent 跑通；通过真实运行数据持续修正流程与知识；最后再增加自治程度和多 Agent 协作。

## 决策请求
建议管理层批准一个 6–8 周的“第一条 AI 业务流水线”试点。目标不是建设万能 AI 员工，而是选一个真实业务场景，把数据、知识、流程、规则、工具、权限和评价标准沉淀成可被 Agent 稳定调用的企业能力底座，并用可量化结果验证价值。
