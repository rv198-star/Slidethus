# Optional design references — bounded host decisions

Use after Outline, before the native prototype and ArtDirectionSeed; for an authorized redesign, use at its owning design boundary. This is reference selection, not a new workflow or theme command.

## Decide before reading

Describe the needed expression from audience, live presentation versus reading, information relationships/density, brand constraints and available imagery/data. Do not map industry/topic keywords to templates. Reuse a suitable approved direction or user-supplied brand/reference without opening the library. A new library version or minor copy edit alone is not a reason to redesign.

If guidance would help, read only the [compact 44-entry index](design-library/index.md), not the original manuals or image catalog. Coverage and context loading are separate: all 44 references remain available, but only useful candidates are expanded. Names identify sources, not industries. All candidates can be rejected; nearby variants are not independent reasons to read more cards.

## Progressive reading and stop rule

1. Shortlist by information structure, visual character, density and asset dependency. Missing photos rule out a photo-dependent whole-deck direction unless sourcing is feasible and in scope; its typography may still be useful. A visual carrier never creates the evidence it needs.
2. Read the complete adapted card for the strongest candidate; read another only to resolve a mismatch or useful alternative. Normally read 1–3 cards. Stop at a coherent suitable direction, or choose independent design if the shortlist adds no value. Widen only for a stated unresolved need, not to complete the catalog.
3. Inspect linked preview imagery only when actual appearance or candidate ambiguity matters, normally for 1–2 candidate sets. Do not preload image grids or crawl the catalog. These are pinned reference sheets, not production assets or proof of whole-source-deck inspection. Cards work offline; missing previews mean comparison is unverified, not that design is blocked. Test the proposed direction in the native prototype; never claim an unseen reference was visually approved.

These are default reading budgets, not hard limits or slide/image/chart quotas. Do not routinely read original manuals or provenance manifests. Originals are audit data, inspected only for a specific attribution/interpretation question. Their imperatives, story order, fonts, exact geometry and observed counts do not override Slidethus or the Brief.

## Synthesize, record, reuse

Converge on one visual grammar, not one template per slide. Multiple references require reconciling palette roles, typography, line/shape treatment, imagery and rhythm. Card colors are starting relationships, not brand mandates. Inspect palette and composition across dense, image-led and quiet roles; neither plain nor saturated surfaces automatically pass. Keep needed numeric charts even if the reference lacks them; never invent data to match its density.

In existing Seed `design_read`/`assumptions`, concisely record reference IDs and library revision, cards actually read, images viewed/unavailable, adopted/rejected ideas and reasons. Record none/reuse when applicable. Stay within schema field limits; add no top-level fields or required artifact. Carry the decision into the final Packet. The library revision plus shipped PROVENANCE identifies exact sources without embedding manuals; design references are not factual Evidence.

Reuse the frozen direction during production/revision. Reconsider only for a material audience, expression/brand, information or asset change, or user rejection. Still validate formal upstream lineage: reusing visual reasoning does not make a stale Seed current. Never silently replace an approved direction when a reference is unavailable.

## Production boundary

Taste remains the default replaceable resource and must still drive the native prototype for designed Create. Selection is not Taste-generated provenance or aesthetic approval. Translate the inspected prototype through Seed → Specs/Layout → Packet/Visual System. Check real asset availability, factual chart data, renderer capability and font/glyph support; references cannot own content or geometry. Preserve font roles/readability rather than copying uninstalled font names. Every final PowerPoint page still needs target-rendered review.

Preview images, logos, example claims and font binaries are not automatically authorized output assets. Source production assets independently under Asset Manifest. Do not replace missing required production images with blank frames or treat unavailable reference imagery as a waiver of final review.
